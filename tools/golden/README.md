# Golden tooling for the EmbeddingGemma 2 port

The real model (`onnx-community/embeddinggemma-2-ONNX`) is not available in CI or the dev sandbox, so correctness of the
parts that depend on it is pinned with **golden fixtures** produced by the reference implementation
(transformers.js running the same ONNX files). The C# golden tests (`Pixelbadger.Toolkit.Rag.Tests/Golden`) compare against
them and **skip** unless both `PBRAG_MODEL_PATH` and the fixtures are present.

| What | Oracle | Generated by | Committed at |
|---|---|---|---|
| Tokenizer ids for ~1,000 varied strings | Python `tokenizers` (Hugging Face) | `tokenizer_parity.py` | `test-assets/golden/tokenizer-parity.json` (done) |
| Text / image / audio tensors + embeddings | transformers.js + the ONNX model | `generate.mjs` | `test-assets/golden/*` (**you run this**) |
| ONNX Runtime plumbing (tiny stand-in graph) | n/a | `make_tiny_text_graph.py` | `test-assets/golden/synthetic/tiny_text_graph.onnx` (done) |

All paths are relative to `Pixelbadger.Toolkit.Rag.Tests/`.

## 1. Generate the model fixtures (once, on a machine with the model snapshot)

Prerequisites: Node >= 20, a local snapshot of `onnx-community/embeddinggemma-2-ONNX` (the `onnx/` folder with
`model.onnx(+_data)`, `vision_encoder.onnx(+_data)`, `audio_encoder.onnx(+_data)`, plus `tokenizer.json`,
`config.json`, `processor_config.json` etc.).

```bash
cd tools/golden
npm install
node generate.mjs --model /path/to/embeddinggemma-2-ONNX
#   (or: export PBRAG_MODEL_PATH=/path/to/embeddinggemma-2-ONNX; node generate.mjs)
```

It writes into `Pixelbadger.Toolkit.Rag.Tests/test-assets/golden/`:

* synthetic, deterministic inputs: `img-square.png` (768x768), `img-wide.png` (640x384), `aud-short.wav` (5.0 s),
  `aud-multiclip.wav` (exactly 30.0 s = one window = three 11.2 s clips). No external media is needed; running with
  `--inputs-only` only rewrites these (and is byte-for-byte reproducible).
* `txt.texts.json` (the 5 queries + 8 documents that were embedded) and, per case (`txt`, `img-square`, `img-wide`,
  `aud-short`, `aud-multiclip`), one `<case>.<tensor>.json` (`{dims,type}`) + `<case>.<tensor>.bin.gz` (little-endian raw,
  gzipped) for every processor output and for the `embedding` (full 768-d `sentence_embedding`);
* `manifest.json` (written last; its presence tells the C# tests the set is complete).

Expected size is roughly 10-15 MB gzipped (dominated by the 2,304 x 768 `pixel_values` of the square image). Review the
list printed by the script, then **commit everything** under `test-assets/golden/`.

If the script fails or a C# test reports `fixture <case>.<tensor> is missing`, the transformers.js release names an
output differently than assumed: add it to the `ALIASES` map at the top of the "Reference run" section in
`generate.mjs` (the C# side reads `pixel_values`, `pixel_position_ids`, `input_ids`, `attention_mask`, `input_features`,
`input_features_mask`, `embedding`). The multimodal call shape `processor(text, image, audio)` follows reference
section 9 and is marked `[verify]` in the script.

## 2. Run the golden tests

```bash
export PBRAG_MODEL_PATH=/path/to/embeddinggemma-2-ONNX
dotnet test Pixelbadger.Toolkit.Rag.Tests --filter "FullyQualifiedName~Golden"
```

Tolerances (reference section 9): `input_ids` exact; `pixel_values`, `input_features` atol 1e-4; `pixel_position_ids` and masks
exact; final embeddings cosine >= 0.9999 after truncating the golden 768-d vector to 256 and re-normalising. They also include
the model card "Red Planet" check (Mars must rank first; scores within 0.05 of 0.675 / 0.853 / 0.747 / 0.778).

When an image/audio test fails, the message says which tensor and flat index differ; the named constants for patch scan
order, within-patch flatten order and (x, y) vs (y, x) position ids in `ImagePreprocessor` (workstream B) and the mel scale /
window / filterbank constants in `AudioPreprocessor` (workstream C) are the knobs to flip.

## 3. Tokenizer parity

The C# tokenizer (`Embeddings/Text/GemmaTokenizer.cs`) is implemented in-house (see its XML doc for why Microsoft.ML.Tokenizers
2.0.0 cannot load a Gemma `tokenizer.json`). `GemmaTokenizerParityTests` compares it with Python `tokenizers` for 1,018
strings (multilingual, code, emoji, whitespace runs, added-token lookalikes, seeded fuzz).

The parity tests look for a `tokenizer.json` in this order: `$PBRAG_MODEL_PATH/tokenizer.json`, `$PBRAG_TOKENIZER_PATH`,
`test-assets/tokenizer/tokenizer.json`. The last one is not committed (33 MB, Gemma terms of use); fetch it with

```bash
tools/golden/fetch-test-tokenizer.sh     # npm pack @lenml/tokenizer-gemma3 -> test-assets/tokenizer/tokenizer.json
```

The fixture was generated from that Gemma 3 file (`tokenizerSha256` is recorded in it). If the tokenizer under
`PBRAG_MODEL_PATH` is a different file (EmbeddingGemma 2 re-purposes some added tokens), the test compares only the
plain-text cases against it. To pin parity against YOUR tokenizer.json completely, regenerate and commit:

```bash
pip install tokenizers
python tools/golden/tokenizer_parity.py /path/to/embeddinggemma-2-ONNX/tokenizer.json \
       Pixelbadger.Toolkit.Rag.Tests/test-assets/golden/tokenizer-parity.json
```

Note on `<bos>`/`<eos>`: the Gemma 3 `tokenizer.json` template adds only `<bos>`; EmbeddingGemma 2 wraps `<bos> ... <eos>`.
The C# tokenizer ignores the template and `GemmaInputBuilder` applies the framing exactly once, so both files behave the same.

## 4. Tiny ONNX stand-in graph

`make_tiny_text_graph.py` (needs `pip install onnx numpy`) regenerates
`test-assets/golden/synthetic/tiny_text_graph.onnx`, a few-KB graph with the same inputs/outputs as `model.onnx`. It lets
`OnnxGemmaTextModelTests` exercise real ONNX Runtime calls (int64 inputs, empty `[0,512]` tensors, feature wiring, output
extraction) in CI without the 1 GB model.
